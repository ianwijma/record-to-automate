Author: GPT-6 Astra high. Revision date: 2 November 2026. Planning only: no implementation, installation, configuration changes or live platform/provider tests. Read both v1 plans and mutual reviews; no peer v2 read. [DECISIONS.md](../../DECISIONS.md) governs; [PLAN.md](../../PLAN.md) supplies baseline requirements. Recommendations below remain unapproved. Acceptance statements describe future evidence, not verified properties.

## 1. Decisions and boundaries

Both X11 and selected Wayland support, offline core, independent copies, runtime Jev and user-owned CLI integrations remain release requirements. No linked copies, general graph cycles, workflow calls, schedules, arbitrary scripts or detection-evasion claims are added.

## 2. Capability proof and setup

After authorization for future spike work, build a harmless fixture with input-receipt ledger, visual timecode, moving/repeated/absent targets, editable text, dragging, delayed readiness and popup branches. Separate setup/build allowance from each capability investigation. Before each cell, record candidate, scope, sample matrix, numeric tolerance, uncertainty bound and investigation budget. Proposed evidence threshold: no lost/misassociated events or wrong-target dispatches in the declared corpus; report denominators and finite-sample limits. Zero observed errors is not population accuracy. Measure latency distributions before choosing limits under D6.

Budget per capability, not two attempts for an entire backend. At budget exhaustion classify passed, failed with reproducible counterexample, or inconclusive; distinguish implementation defects from platform limits. Escalate alternatives and costs through D2/D4 without silently changing desktop, interaction model or required platforms.

| Cell | Candidate and required proof |
| --- | --- |
| Pixels | X11 GStreamer/X11 capture; Wayland ScreenCast/PipeWire. Prove actual capture timestamps, target identity, occlusion/fullscreen behavior, resize, loss and permission denial. |
| Passive observation | X11 RECORD plus XI2 source identity where demonstrated. Wayland candidate W1: compositor delivery hook carrying recipient surface, accelerated coordinates, button/key edge and timestamp; a GNOME extension is viable only if those hooks exist. W2: deeper Mutter bridge, separately approved. W3: XWayland RECORD/XI2 with explicitly limited client coverage, measured per application. Do not assume Last Z/Proton or Chrome's active backend. |
| Association | Compare physical move-click-move, sub-frame clicks, drags and focus changes against fixture receipts. Prove event-time recipient and accelerated coordinates with bounded clock uncertainty. evdev deltas, pointer polling, shell stage callbacks and video cursor metadata alone do not prove this. |
| Dispatch/geometry | XTEST on X11; authorized RemoteDesktop methods/EIS where exposed on Wayland. Prove native Wayland and XWayland separately, source/client/input transforms, mixed scaling, monitor rotation/hotplug and focus theft. |
| Abort/release | X11 key grab; Wayland introspected GlobalShortcuts or compositor keybinding with dedicated guard channel. Optional broker chord mode below. Prove fullscreen/out-of-focus abort, route revocation, engine death, guard death and physical-user overlap. |

Portal interfaces are specifications, not installed-backend guarantees. Record interface versions and method availability; no GNOME version claim is inferred from forums. InputCapture redirects activated input and is not evidence of passive observation. Cursor buffer metadata is a cross-check only. [GlobalShortcuts](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html), [InputCapture](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.InputCapture.html), [PipeWire metadata](https://docs.pipewire.org/group__spa__buffer.html), [RemoteDesktop](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html).

**Optional broker contract:** propose a systemd service, explicit polkit authorization for the active local seat/session, and IPC peer UID/PID/session checks. No standing input-group grant. Resolve an allowlisted device set from that seat; no arbitrary paths, grabs, command execution or dispatch interface. Lease binds peer, target, devices, mode and expiry. Recording mode correlates events with authoritative delivery-time recipient evidence inside a bounded volatile buffer; unknown/non-target events are dropped before forwarding/persistence. Overflow records a gap, never guesses focus. Run mode retains only ephemeral abort-chord state and emits an abort signal, not a key stream. Lock, logout, session switch, peer loss, bridge loss or expiry closes descriptors and clears buffers. Visible setup/recording/run indicators, revocation and uninstall remove authorization/service artifacts. Threat-model proof includes non-target/password-field events never reaching app logs or `events.jsonl`; target-sensitive masking is a separate D6 policy. If recipient evidence is unavailable, this candidate fails.

Setup UI and a diagnostic command explain capabilities, precise permissions, extension/broker installation/removal, denied/revoked permissions and unsupported cells. Measure ScreenCast/RemoteDesktop prompts, restore-token behavior and repeated-session setup; promise no prompt-free route before evidence. A missing independent abort route or failed release gate blocks that backend's release eligibility, with residual limitation escalated rather than hidden.

## 3. Process, evidence and dispatch contracts

Use `apps/desktop/{main,preload,renderer}`, `packages/{schema,engine,geometry,recording,store,evidence,providers}`, native capture/vision/guard processes, optional compositor integration and fixture/scenario suites. Sandbox renderer, enable context isolation, disable Node integration and expose validated operation-specific preload methods. Main supervises a TypeScript engine. The input guard alone dispatches; its scheduling, bounded command queue, abort channel and lease timer are independent of UI, capture, encoding, storage, vision and providers. Storage never blocks guard cancellation/release. Validate protocol versions, payload sizes, request IDs and asset handles.

Core records:

- `Observation`: ID, source/epoch, actual capture interval mapped to monotonic time, uncertainty, frame hash, dimensions/transforms and recipient/focus evidence. Receipt/encode/fsync time is not capture time. Clock discontinuity invalidates the epoch.
- `LocateResult`: Found, Absent, Ambiguous or Unavailable; candidates and method-specific score/calibration, never interchangeable probabilities.
- `AuthorizationEvidence`: all still-relied-on observations, predicates, semantic regions and transforms, including branches authorizing later actions until revalidated or explicitly no longer relevant.
- `DispatchPermit`: single-use run/revision/occurrence/attempt/lease IDs, evidence digest, epoch, deadline, operation, final geometry and expected recipient.
- Outcomes distinguish rejected-before-dispatch, attempted/acknowledged, verified and `OutcomeUnknown`; transport acknowledgement does not prove application success.

For every relied-on observation i, let `earliestCapture_i = captureEstimate_i − totalUncertainty_i`. The deadline is the minimum of `earliestCapture_i + approvedValidityBudget_i`. Unknown uncertainty or missing relevant evidence blocks authorization. At dispatch, all evidence must remain within that deadline and retain valid source, geometry and recipient identity.

**Persistence-to-dispatch order:** acquire/locate; persist necessary lossless evidence assets while processing; finish every required asset and directory durability barrier; append/fsync intent referencing those assets and the complete authorization basis in every run mode; submit permit. Guard checks lease/revocation, single use, epoch, recipient, geometry and deadline after those writes and after queueing, immediately before input. Slow writes or queueing expire authorization and cause bounded re-observation, not timestamp renewal. A confirmation frame that changes authorization must itself be persisted and linked before a replacement intent/permit. Target pixels alone cannot refresh semantic evidence elsewhere. Observe-to-dispatch races remain measurable limitations.

One recorder or executor owns a desktop lease. Preflight freezes revision, validates capabilities/assets/outputs/evidence capacity and confirms abort availability. Reconnect or loss of the abort route revokes pending permits and stops execution. Pause/abort revokes lease first, rejects queued operations, cancels workers and releases owned inputs. Long holds/drags use bounded cancellable segments and guard-enforced maximum holds, not an uninterruptible command batch. Bound backend submissions as well as application queues; report any already-submitted, non-revocable input. Physical interaction may be a tested secondary abort signal, never a substitute for the reserved route.

An engine-death watchdog only works while the guard remains alive. A killed guard cannot clean up. Evaluate backend disconnect release, isolated synthetic-device ownership and, optionally, a supervisor ledger/fresh connection. Prove actual releases, no duplicate dispatch after reconnect and no release of the user's overlapping physical holds. Reporting a press before sending it creates an uncertain ownership window; the supervisor is not presumed safe. Failed ownership/release evidence leaves the backend gated; document manual recovery and escalate any proposed limitation to the user.

`OutcomeUnknown`, live or after restart, stops execution and prohibits automatic replay/recovery retry. Resume requires reconciliation/user resolution and fresh readiness/evidence; no resume bypasses unknown outcomes.

## 4. Recording, editing and execution model

Preserve raw source timestamps, wrap/drift calibration, uncertainty and media PTS mapping. Lossless ring-buffer frames supply crops/pre-evidence; scrubbing video never supplies authoritative templates. Associate pre/post frames conservatively and show unavailable associations. Record and replay are mutually exclusive; drain queues between leases. Source-device classification is supplementary evidence, not a universal synthetic marker.

Extract editable clicks, double-click grouping, drags, scroll packets, holds and key transitions. Preserve repeats, physical code **namespace/platform**, device, modifiers, keysym where available, layout/keymap identity and raw events. Physical keys are not committed text. Explicit authored text actions declare their insertion method and capabilities. Layout mismatch blocks physical replay pending explicit remapping/confirmation; no silent keymap mutation. Test non-US layouts, AltGr, dead keys, Compose, IME and non-ASCII text independently per backend. Unproved text/masking capabilities remain unavailable.

Recommend a tree of sequences/linear sections, actions, waits, if/else and joins. Checks return true, false or unknown/error: completed absence may mean false; capture, recognition or provider failure cannot. Failure policies are stop (default), pause, or an explicit nonrecursive recovery block with `retry-step | continue | stop`. Recovery counters persist per failed occurrence and run, across retry/resume; budget consumption is durable before entry. Exhaustion stops. Retry acquires new evidence; unknown side effects cannot retry. Recovery annotations do not introduce arbitrary graph back-edges. Definite value availability includes both branches and recovery-continue paths.

Actions, Flow and Values edit one document. Source media, executable revisions and runs stay distinct. IDs identify steps, targets and outputs separately; `ValueRef` includes producer/output IDs and type. Names are labels. Independent copy creates fresh executable IDs and remaps references inside the copied closure; outside producers retain references only when valid at the destination, otherwise require explicit rebind. Outside consumers still refer to the original. Immutable media may be shared.

Re-record stages a take for a selected linear range. Show starting-screen guidance and an advisory similarity check, then old/new actions and impacted consumers. User-confirm step, target and output mappings separately; preserve an ID only for explicitly confirmed compatible identity/meaning. Equal type or similar pixels is not equivalence. New entities get fresh IDs; missing/incompatible outputs remain invalid until repaired. Commit mappings, bindings and replacement atomically; invalid drafts save but cannot run. Undo restores branches/bindings/source links without altering independent copies or external effects.

Attach selects a running application with ambiguity handling. Launch uses a locally verified Steam identifier, followed by separate window resolution and visual readiness stages with bounded failure explanations. Do not assume request success, stable geometry or process appearance proves readiness.

## 5. Persistence and file effects

Propose `project.json`, immutable `revisions/<hash>`, `takes/<id>`, content-addressed `assets` and `runs/<id>` journals. A single writer fsyncs asset files, publishes them and fsyncs affected directories; then fsyncs/publishes revision and history-ancestry files and their directories; finally fsyncs the replacement manifest file, atomically publishes it and fsyncs its parent directory. Newly created take/run directories receive the same parent ordering before use. Head is authoritative; indexes/history summaries rebuild from immutable ancestry. Interrupted tails are detected, uncommitted files quarantined and only proven-unreferenced staging files collected. Active takes/runs finalize immutable chunks. File fsync alone does not persist directory entries. [Linux fsync](https://www.man7.org/linux/man-pages/man2/fsync.2.html)

Validate checksums/references on recovery; preserve the last coherent head and surface incomplete media/history. Migrations create validated revisions/backups; future schemas open read-only. Export materializes referenced assets; import enforces path/size limits. Retention includes all retained revisions/takes/runs. Fault-inject each publication boundary; distinguish process-kill recovery from power-loss claims and declare tested filesystem/mount/storage scope.

D5 recommends create-new outputs only; other modes need their own collision, atomicity and reconciliation contracts. Persist logical output identity `(run, occurrence, output-slot)`, selected path and content hash before writing. Retries of that logical effect reuse identity despite distinct attempt IDs. Stage in destination directory, fsync file, publish without replacement, fsync directory, then durably acknowledge. Reconcile missing acknowledgements against identity/path/hash; collision or ambiguity becomes `OutcomeUnknown`, never another file. Guard directory containment against traversal/symlink races. If tested no-replace/durability primitives are absent, block that destination and offer a supported location; no unsafe overwrite fallback. Editor undo does not remove external output effects. Persisted evidence values do not imply cross-run value scope.

## 6. Recognition and geometry

Evaluate Tesseract/OpenCV against labeled fixture and representative Last Z/Chrome frames: stylized text, scale/motion, decoys, absence, repeated icons and animation. Separate calibration and held-out evaluation; report wrong targets, misses, ambiguity, latency, sample counts and uncertainty by target class. A failure triggers bounded repair or evaluation of another local non-generative OCR engine under D2; optional Jev cannot replace the offline requirement.

Each action selects one locator. Recommend recorded drafts show a candidate image crop and captured coordinates as evidence, requiring target review before execution. No automatic visual-to-fixed fallback on absence, ambiguity, staleness or unavailability. Separately authored fixed/region targets remain supported with fresh source/focus/geometry checks; no fallback-chain feature is needed initially.

Keep search area, located bounds, user-confirmed safe area and point distinct. Compose crop/frame/client/compositor/input transforms; invalidate on source change. Intersect target/client bounds, subtract exclusions and apply inset. Recommend rectangles initially; sample only eligible integer dispatch points whose inverse transforms remain safe, recording seed/algorithm. Empty geometry fails. Position-only variation never changes timing; deliberate holds remain explicit. Geometry tests include scaling/rounding and fixed targets without variation.

## 7. Debug and Runs

Per-workflow debug captures raw pre-evidence for every action, check and locator attempt, including false conditions, failures, recovery and file-output actions; capture post-action evidence after completion/verification. Record source gaps instead of fabricated frames. Trace revision/occurrence/attempt, original evidence, candidates, OCR/values, branch, transforms/safe area/point, age at dispatch, requested operation, outcome and provider metadata without credentials. Separate overlays and deduplicate assets by content.

Every mode durably journals side-effect intent and the evidence needed for authorization/reconciliation; debug adds full inspection coverage. Pre-dispatch storage failure prevents dispatch. Post-dispatch failure stops/releases and marks incomplete/unknown effects. Best-effort emergency reporting may also fail; all-storage failure cannot guarantee persistent basic logs. Surface status in memory and infer incomplete runs on restart. D6 must resolve retention/redaction and any proposed degraded continuation; none is silently enabled.

Runs provides chronological attempts/path, before/after, overlays, values and historical revision navigation. Replay has no dispatch capability; starting a new run is separate. Test zero input, corruption/gaps, disk-full/EIO and history after edits.

## 8. Optional providers

Settings delivers enabled state, installed CLI path/version, auth readiness, models/capabilities, connection test, explicit online data selection and billing category. Use installed unmodified binaries and their own login, never copied tokens or silent API-billing substitution. Recheck product/account eligibility before advertising support. [Claude integration conditions](https://code.claude.com/docs/en/legal-and-compliance)

Build versioned invocation profiles with exact arguments, effective configuration sources, policy exceptions, image route and proven capability matrix. Current Claude docs describe `-p`, structured output, `--safe-mode`, `--restricted` (v2.1.248+), `--tools` and `--strict-mcp-config`; safe mode retains authentication but managed policy can still execute hooks. Evaluate an empty tool set with documented image-content input, or restricted Read confined to staged images. Do not bypass policy; reject an incompatible profile. [Claude CLI](https://code.claude.com/docs/en/cli-reference). Bare mode is unsuitable for subscription login. [Programmatic mode](https://code.claude.com/docs/en/headless)

Codex candidates include `exec --json --output-schema`, `--ignore-user-config`, `--ignore-rules`, `--sandbox read-only`, `--ephemeral` and `-i`. Documentation says ignoring user config retains authentication; this does not prove hooks/plugins/MCP isolation. Determine supported version floors and effective controls before enabling. [Commands](https://learn.chatgpt.com/docs/developer-commands?surface=cli), [configuration](https://learn.chatgpt.com/docs/config-file/config-reference).

Probe exact profiles with sentinel hooks/tools/MCP, unchanged user settings, eligible authentication and approved image input. If isolation and login cannot coexist, reopen D8. Spawn argument arrays with bounded I/O/deadlines in app-owned scratch directories; no desktop authority. Validate proposed edits into one reviewable undoable revision. Auth/limit/refusal/model/malformed/transport failures are typed. Cancellation revokes control immediately, terminates subprocess groups with bounded grace and rejects late responses retaining original request/revision/observation IDs.

Jev runtime judgments/targets remain explicit hosted capabilities. Box alone is insufficient; bind presence, uniqueness, semantic judgment, bounds and crop transforms to the same observation. [Jev Box](https://docs.typesafe.ai/primitives/box). A delayed result retains its original evidence/deadline. To replace expired evidence, rerun the complete relevant decision on durable fresh evidence; local checks qualify only if they independently establish **all** required predicates. Comparing target pixels or finding the same button cannot refresh surrounding semantics. Unknown is never false, including branch judgments. Test unchanged target/changed context, ambiguity and animation. OpenRouter scope stays D8; if selected for release, require a completed adapter, Settings and equivalent tests, not a stub.

## 10. Remaining High/Blocker gates
