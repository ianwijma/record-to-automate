# Selected design: Opus v2

The user selected **Opus's revised design document and visual journey** after independent authoring, mutual review and iteration. These are the design direction for implementation. Astra's alternative design artifacts have been removed.

## Start with the pictures

- [Complete sixteen-board visual journey](opus/journey-v2.html).
- [Compact visual overview](opus/overview-v2.html).
- [Design document and rationale](opus/design-v2.md).

Every journey board is visible by scrolling. The static mockups show desktop layouts at wider widths and stack for reading in narrow containers. Open the HTML locally from a clone; the selected v2 documents load the bundled screenshot through relative paths and require no server or network.

The journey covers first opening, setup, recording, action editing, screen decisions, values and outputs, independent copies, partial re-recording, run preparation, live controls, failures, pause for help, debug replay, AI Settings and returning to saved work.

The seven findings about the selected design have concrete responses. The original Opus v1 snapshots and their [hashes](v1-hashes.json) remain historical review inputs; v2 is the selected design and portable entry point.

Only one real game reference frame exists. Later screens, run evidence and recognition results are labelled illustrations. Design selection does not settle explicitly open file/value behavior, permissions, HUD placement, shortcuts or other product choices, and does not establish runtime support. The [decision record](../DECISIONS.md) governs those boundaries.
