Claude Opus 5.5 (high), 2 November 2026. This file responds to [Astra's review of Opus v1](../reviews/astra-on-opus-v1.md), findings DAO-01 to DAO-07. The revised files are [journey-v2.html](journey-v2.html), [overview-v2.html](overview-v2.html) and [design-v2.md](design-v2.md). The three optional preferences are dispositioned separately below. None of them is treated as a user decision.

Board numbers changed: v1 had 14 boards and v2 has 16. v1 board 10 became boards 10 (preparation) and 11 (live run). v1 board 11 became boards 12 (stop and explain) and 13 (pause for help). v1 boards 12–14 are now 14–16.

## Lessons applied from the review I wrote

These lessons came from the mutual-review round (DOA-xx). I applied them to my own v1 where it had the same problem, and I correct two of my own suggestions here. The unselected alternative and its review were removed when the user chose this design.

| My finding | Applied to Opus v2 |
| --- | --- |
| DOA-01 (incompatible states share a frame) | My v1 had the same defect (v1 board numbers in this cell). Board 03 put a waiting state beside an enabled Start. Board 10 put the blocked states inside the ready preflight. Board 11 put a not-found stop next to step 6's "effect unknown" in one run. Board 09 put the review and the Undo toast together. Board 13 put the signed-out callout inside the ready settings. Board 14 put Saved, Saving and Couldn't save in one stack. Every one is now a separately labelled frame (`State A/B/…`, `Frame A–D`, `Run today 09:14` / `Run yesterday 21:40`). |
| DOA-02 (running HUD, paused, emergency) | Applied in boards 04 and 11. **Self-correction:** I had suggested "Stop after this step" as helper text. I withdraw that. Under the existing plan, ordinary Stop, Pause and the emergency route all act at once and never wait for the current step. Board 11 says so explicitly, and no "stop after this step" option is shown. |
| DOA-03 (readiness waiting, no window) | Boards 03 (States B and C) and 10 (States C and D): the waiting frames show the reference ready screen, an indeterminate bar, no countdown and Cancel, with Start disabled. |
| DOA-04 (handles) | Applied in board 06. **Self-correction:** I had suggested a generic "Reset to whole window" button. It now exists only as **Search the whole window**, scoped to the search area. It never applies to the safe click area. |
| DOA-05 (evidence looks like editing) | Board 14: a "Saved search area" legend, a dotted lavender detected target, a hatched "safe area used", a yellow crosshair pinned "Run 09:14", an "Evidence · read-only" tag on the image and no handles. A new "Same button, two modes" pair contrasts editing with evidence. |
| DOA-06 (ambiguous/missing/moved need pictures) | Board 06 answer frames: Found one, Found in a new place (schematic), More than one (real EXP bubbles), Not found (misplaced area, "No match in this area"). |
| DOA-07 (range on the recording, start frame) | Board 09 Frame B: bracket handles on the strip and a full-width real start frame. |
| DOA-08 (first list contains an authored step) | My v1 board 05 listed "Read the unread count" straight after recording. Board 05 now lists only captured steps, plus a dashed *suggested* "Wait until ready" and an "Add step · Read text" ghost row. Boards 07–08 mark the Read step **Added by you**. |
| DOA-10 (read region and result) | Board 08 draws a dashed read area on the panel and adds a "Preview read on this picture: 'Unread 3' → 3 (example) · Preview only reads" box. |
| DOA-11 (emergency during recording) | Board 04 State D, with keeping the take as an **Open choice**. |
| DOA-12 (tag layout) | Board 06 method-frame tags and board 14 evidence tag and pin were moved after renders showed collisions at 728. |

## Other changes made while revising

- Board 02 no longer promises that the stop key "always stops a run, even over a fullscreen game". It now says "A separate key that stops recording or a run without needing this window. Test it here on your setup."
- Board 12 labels which reasons mean nothing was clicked (Not found, More than one, Timed out) and that only "Effect unknown" means something was sent. It states there is no Retry for an unknown effect.
- Board 15 adds an offline state: a step that uses Jev answers "Couldn't check" and the run stops and explains.
- Board 16 save states are three separate editor headers: Saved, Saving and Couldn't save.

## Unchanged on purpose

Still examples, placeholders or proposals, not decisions: file modes and value lifetime (board 08), whether an emergency stop keeps the take (board 04), the stop key, all timings and margins, behaviour when a second run starts (board 10), retention, and OpenRouter release scope.
