# P0.5 Minimal guard: one request, current recipient and independent abort

[Delivery index](../../DELIVERY-PLAN.md) · [Milestone M0](../milestones/M0.md) · [Implementation plan](../../IMPLEMENTATION-PLAN.md) · [Requirement and W-package mapping](../coverage.md)

Read [execution rules](../execution.md) and [safety invariants](../safety.md) before executing. Consult [experimental defaults](../defaults.md) for implementation constants and [validation contract](../validation.md) when implementing or running acceptance cases. Follow linked dependencies for their contracts; execute only this packet.

- **Outcome**: the host’s guard mode dispatches a bounded click only with a current run generation, fresh observation metadata and checked recipient; abort does not depend on the engine.
- **Depends on**: [P0.2](P0.2.md), [P0.3](P0.3.md).
- **Files**: `native/x11/guard/{guard.c,abort.c,abort.h,recipient.c,recipient.h,owned.c,owned.h}`, `packages/host-protocol/src/guard.ts`, `validation/cases/m0/{guard.ts,abort.ts}`.
- **Steps**:
  1. Use a command reader, a dispatch worker and an abort thread with separate X connections after `XInitThreads()`. One bounded request slot, no backlog or generic permit service. Keep X calls outside locks used by abort; capture, logging and disk are never on its path.
  2. `START run=<id> target=<xid> settle_ms=<profile-value>` opens one run generation and replies `STARTED generation=<runId:counter> next_seq=1`. Observe target lifetime/geometry independently on the guard’s connection; unmap/reparent/destroy or geometry change invalidates that generation. Capture’s epoch is separately checked by the engine, not assumed numerically equal to the guard’s counter. `ARM chord=<keysym+mods>` grabs all Lock/NumLock variants and verifies success with `XSync`/error handling. Require the direct abort pipe on fd 3, chord, watchdog and parent-EOF handling before replying `ARMED`. Failure leaves dispatch disabled. `HEARTBEAT` feeds `watchdogMs`.
  3. `SUBMIT generation=<g> seq=<n> obs=<id> deadline_ns=<ns> content_earliest_ns=<ns> geom=<rx,ry,w,h> kind=click x=<rootX> y=<rootY> button=<n>` accepts exactly the next action sequence once. Mark the sequence consumed even if rejected; a rejection terminates the run. A second pending/in-flight request returns `E_BUSY`. No separate permit-ID cache, lease broker or reusable queue is needed.
  4. Immediately before injection check armed/active generation, sequence, content time after the prior settled boundary, unchanged source/geometry and deadline. Query actual pointer destination using the guard’s own X connection, descend the window tree and require the expected client/descendant. Reject decorations, foreign cover windows and unqualified grabs. For later key actions, query actual input focus and apply the same target-tree rule. Missing/stalled recipient evidence rejects, never authorizes.
  5. Send move → button down → button up as one bounded click occurrence. Recheck revocation/deadline before new input, track owned down/up state, and always allow necessary cleanup releases. Reply `ACK generation seq t_start t_end`; ACK means injection attempted, not application success. Advance the settled fence only from a known ACK plus the experimental settle duration. Test-only bounded holds allow abort testing before public hold actions exist.
  6. Pipe/chord/watchdog/EOF or `STOP mode=pause|stop|abort` first invalidates the generation and pending slot, prevents new input and releases guard-owned inputs. Emit `ABORTED reason released uncertain`. Keep any in-flight X-call race bounded/measured; do not claim that a blocked X server or guard SIGKILL is solved. Unknown release state remains explicit.
  7. Send bounded diagnostic events to a nonblocking log sink; overflow marks an evidence gap and stops normal progress. The abort thread never waits for a ledger write. The harness persists diagnostics outside the guard.
- **Contracts/errors**: `E_NOT_ARMED`, `E_NO_RUN`, `E_GENERATION`, `E_EFFECT_SEQ`, `E_EXPIRED`, `E_STALE_OBSERVATION`, `E_GEOMETRY`, `E_RECIPIENT`, `E_BUSY`, `E_REVOKED`, `E_BACKEND`. `permit` in later packets means this checked dispatch request until [P7.1](P7.1.md) introduces production machinery. Abort/stop is terminal; pause/resume needs a fresh generation.
- **Acceptance**: `bun run validate --case m0.guard.*,m0.abort.*`; cases below use real Xvfb receipts and a direct host client as the engine surrogate; [P0.6](P0.6.md) adds integrated engine variants. Key-only cases are registered with [P2.4](P2.4.md); unavailable operations never silently pass.
- **Artifacts**: guard and fixture ledgers, abort latency and recipient-query timing.
- **Out of scope / escalate**: guard-death release and full physical-overlap qualification are [P7.1](P7.1.md); branches, compound public actions and a multi-entry queue are unnecessary for the first run. A failed independent-abort or recipient check blocks dispatch.
