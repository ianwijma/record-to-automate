# P1.1 Existing matcher candidate and bounded dependency check

[Delivery index](../../DELIVERY-PLAN.md) · [Milestone M1](../milestones/M1.md) · [Implementation plan](../../IMPLEMENTATION-PLAN.md) · [Requirement and W-package mapping](../coverage.md)

Read [execution rules](../execution.md) and [safety invariants](../safety.md) before executing. Consult [experimental defaults](../defaults.md) for implementation constants and [validation contract](../validation.md) when implementing or running acceptance cases. Follow linked dependencies for their contracts; execute only this packet.

- **Outcome**: a thin `locate(frame, template, searchArea) → LocateResult` adapter around the existing OpenCV candidate, with local dependency and latency evidence.
- **Depends on**: [P0.6](P0.6.md).
- **Files**: `packages/vision/{package.json,src/image.ts,src/match.ts,src/result.ts,test/match.test.ts}`, `packages/vision/adapters/opencv.py` (only if the subprocess route is chosen), `docs/evidence/matcher-feasibility.md`.
- **Steps**:
  1. Inspect available local OpenCV bindings/runtimes. Try the smallest working route: an existing Python `cv2` subprocess if available, otherwise a bounded project-local dependency install/build within current authority. Pin the version and record the exact import/build command, license and native requirements. Stop after one dependency failure and one targeted fix/rerun within the two-hour limit.
  2. Use the library’s existing template matcher at one image scale. Adapt the score map into distinct candidates with simple overlap suppression and explicit absent/ambiguous/uncertain thresholds. Reject low-information templates. Do not implement custom correlation, pyramids or multiscale search.
  3. Only after a **named** failure (dependency/build incompatibility, unavailable packaging route or measured latency exceeding the capture budget), record command/error/timing and try the simplest available existing alternative under the remaining timebox. Do not replace a working candidate for speculative portability. If no existing candidate fits, leave image support blocked and continue the fixed path; a bespoke CV project is not the fallback.
  4. Return `Found{box, score}`, `Absent`, `Ambiguous{candidates}` or `Unavailable{reason}`. Clamp/validate the search area. Pin fixture thresholds in experimental config with evidence; no game accuracy claim.
- **Contracts/errors**: empty area, flat template, decode failure, subprocess failure/timeout or uncertain score return `Unavailable`, never `Absent`. Distinct strong peaks return `Ambiguous`. Scores stay internal. Matcher has no input authority or network use at runtime.
- **Acceptance**: `bun run validate --case m1.match.unit,m1.match.dependency`. Exact, translated, duplicate, absent, decoy, noisy, flat and edge-clipped images; record 800×600 latency. Dependency absence is `missing`; a broken selected route is `fail`. No silent fallbacks or increased freshness budget to mask a slow matcher.
- **Artifacts**: exact dependency/build evidence, per-case outcomes/scores and latency distribution.
- **Out of scope / escalate**: rotation/scale invariance, game-wide recognition research, custom CV, production binding selection (D-RECOG).
