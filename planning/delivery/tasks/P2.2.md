# P2.2 Workflow schema v0 and plain preview save/reload

- **Outcome**: validate, save and reload one workflow JSON with ordinary referenced image files; an edit survives restart.
- **Depends on**: [P0.6](P0.6.md).
- **Files**: `packages/schema/{package.json,src/workflow.ts,src/validate.ts,test/*.test.ts}`, `packages/store/{package.json,src/project.ts,src/assets.ts,test/*.test.ts}`.
- **Steps**:
  1. Schema `r2a.workflow/1-dev`: `{id, name, revision, target:{wmClass,titleIncludes?}, steps:Step[]}`. A step has `{id, kind:"click"|"key", source?:{takeId,eventIds,preFrame:assetId}, locator?, button?, key?:{namespace,keycode,keysym,state,keymapHash}, settleMs?}`. Click locator is exactly one of fixed `{point}` or image `{template:assetId,offset,searchArea,draftStatus,flags}`; keys use current target focus, not an image locator.
  2. `validate(doc) → {runnable, issues[]}`. Missing assets, unsupported gestures, unreviewed drafts and invalid geometry block run but allow saving. Accept M0 documents by an explicit conversion; do not maintain two interpreters.
  3. Use `$R2A_DATA_DIR` (dev default `~/.local/share/record-to-automate-dev`): `projects/<id>/workflow.json`, `assets/<assetId>.png`, `takes/<takeId>/`, `runs/<runId>/`. IDs resolve under the project root; reject traversal/symlinks outside it. Write assets before documents reference them; preserve source files while referenced.
  4. Serialize writes per project. `saveRevision(id, baseRev, doc)` checks the current numeric revision and publishes via temp-file rename; reject stale `baseRev` with `E_CONFLICT`. Return the new revision. No immutable manifest, content-addressed store, index, garbage collection or per-save durability protocol yet.
  5. On run start copy the exact saved document and its referenced bytes into a run snapshot; edits afterwards cannot change execution or its record. A hash is an integrity check, not an asset-store architecture. Restart detects incomplete files and blocks them; it never resumes interrupted input.
- **Contracts/errors**: `E_SCHEMA`, `E_CONFLICT`, `E_ASSET_MISSING`, `E_IO`. Save failure preserves the prior readable file and current unsaved UI draft; UI says Saving/Saved/Couldn’t save accurately. This guarantees the tested ordinary save/reload behavior, not power-loss durability.
- **Acceptance**: `bun run validate --case m2.schema.unit,m2.store.save-reload,m2.store.failed-save,m2.store.conflict`. Verify edited fields and referenced pixels after reopen; inject a write failure before rename and preserve old bytes. Production crash publication tests are [P7.2](P7.2.md).
- **Artifacts**: before/after documents, referenced image hashes and error evidence.
- **Out of scope / escalate**: D-STORE production format/durability, migrations and immutable publication in [P7.2](P7.2.md).
