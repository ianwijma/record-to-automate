# P0.3 X11 fixture target with receipt ledger and visual clock

[Delivery index](../../DELIVERY-PLAN.md) · [Milestone M0](../milestones/M0.md) · [Implementation plan](../../IMPLEMENTATION-PLAN.md) · [Requirement and W-package mapping](../coverage.md)

Consult [experimental defaults](../defaults.md) for implementation constants and [validation contract](../validation.md) when implementing or running acceptance cases. Follow linked dependencies for their contracts; execute only this packet.

- **Outcome**: `r2a-x11-target` draws deterministic scenes, logs every input it receives, and paints a frame counter that can be read back from pixels.
- **Depends on**: [P0.2](P0.2.md).
- **Files**: `fixtures/x11-target/{target.c,scenes.c,scenes.h,README.md}`, `validation/cases/m0/fixture.ts`.
- **Steps**:
  1. Create an 800×600 window with `WM_CLASS=r2a-x11-target` and a title set by `--name`. Accept the command-line options `--ledger <path>`, `--scene <id>`, `--seed <n>` and `--control <fifo>`. The control FIFO takes the commands `scene <id> [args]` and `quit`.
  2. Draw a scene as a list of named elements `{id, rect, kind: button|icon|text|decoy}`, each with a procedural, high-contrast pattern. M0 scenes: `grid` (labelled buttons), `hold` (one press-hold area) and `cover` (an element that another window will cover).
  3. Paint the visual clock: a 32-bit frame counter as a 32×1 strip of 8×8 black and white cells at window position (0,0), with two calibration cells. Repaint at about 60 Hz. For each counter value, append `{t:"paint", counter, mono_ns}` to the ledger, recording both request time before paint and completion after `XSync` (these bracket the server paint, not display scanout).
  4. For each received ButtonPress, ButtonRelease, KeyPress, KeyRelease or MotionNotify (at most 1 in 8 motions logged), append `{t:"recv", type, server_ms, mono_ns, x, y, button|keycode, state, element}`. The `element` field names the scene element that contains the point.
  5. When the scene changes, append `{t:"scene", id, elements[]}`.
- **Contracts/errors**: the ledger is JSONL, flushed per line. The fixture never sends input. It contains no automation logic.
- **Acceptance**: `bun run validate --case m0.fixture.ledger,m0.fixture.scenes` on Xvfb. An `xdotool` click at each `grid` element centre yields one recv press and one recv release with the matching `element`. Changing scenes updates the element list.
- **Artifacts**: `ledger.jsonl`, plus a screenshot of each scene taken with `xwd`.
- **Out of scope / escalate**: Wayland and browser fixtures ([P3.1](P3.1.md), [PW.2](PW.2.md)).
