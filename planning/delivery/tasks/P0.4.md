# P0.4 Capture helper and clock calibration

[Delivery index](../../DELIVERY-PLAN.md) · [Milestone M0](../milestones/M0.md) · [Implementation plan](../../IMPLEMENTATION-PLAN.md) · [Requirement and W-package mapping](../coverage.md)

Read [execution rules](../execution.md) and [safety invariants](../safety.md) before executing. Consult [experimental defaults](../defaults.md) for implementation constants and [validation contract](../validation.md) when implementing or running acceptance cases. Follow linked dependencies for their contracts; execute only this packet.

- **Outcome**: `r2a-x11-host --mode capture` captures the target window's on-screen region with a conservative capture interval, tracks a source epoch, and maps X server time to monotonic time.
- **Depends on**: [P0.2](P0.2.md), [P0.3](P0.3.md).
- **Files**: `native/x11/capture/capture.c`, `packages/host-protocol/src/capture.ts` (typed client), `packages/engine/src/observation.ts`, `validation/cases/m0/capture.ts`.
- **Steps**:
  1. `ATTACH window=<xid>` selects `StructureNotifyMask` on the client window and its frame ancestor and starts `epoch=1`. Every ConfigureNotify (position or size change), Unmap, Map, Reparent or Destroy increments the epoch.
  2. `CAPTURE id=<req> out=<path>` does the following, recording `t_req` and `t_done` as monotonic time:
     1. Translate the window's coordinates to root.
     2. Capture the root region covering the window with `XGetImage`; consider XShm only if measured latency requires it. Bracket the pixel-read call with monotonic timestamps; file writes happen afterwards and cannot widen capture time.
     3. Write `R2AF` raw RGBA: a 32-byte header (ASCII magic at bytes 0–3; little-endian uint32 width, height and stride at 4/8/12; zero reserved bytes 16–31), then `height × stride` bytes, RGBA8 with stride at least width × 4. Reject overflow, invalid lengths and dimensions before allocation.
     4. Reply `FRAME id t_req t_done root_x root_y w h epoch map_state`.
  3. `CALIBRATE n=<k>` repeats k times: record `t0`, change a property on a helper-owned window, wait for PropertyNotify (`server_ms`), and record `t1`. Reply with the sample that has the tightest `t1 − t0`, as `offset_ns`, `uncertainty_ns` and `server_ms_wrap`. Handle 32-bit wrap of `server_ms`.
  4. In TypeScript, `makeObservation(frame, cfg)` returns `Observation{source:{xid, epoch}, content: Interval(t_req − captureContentLagBoundMs, t_done), frameHash (sha256 of the file), rootRect}`. This is the only constructor (S12).
- **Contracts/errors**: `E_NO_WINDOW`, `E_UNMAPPED`, `E_CAPTURE` (with an X error code), `E_EPOCH_CHANGED` (when the epoch changed between request and reply) and `E_CALIBRATION`.
- **Acceptance**: `bun run validate --case m0.capture.pixels,m0.capture.epoch,m0.clock.capture-interval,m0.clock.server-mono`.
  - `m0.capture.pixels`: the scene's element rectangles match their expected colour signatures exactly at integer coordinates.
  - `m0.capture.epoch`: moving or resizing the window with `xdotool` increments the epoch, and the next frame reflects the change.
  - `m0.clock.capture-interval` (check with metrics): for 300 captures, decode the counter strip, look up the paint interval and record conservative lag bounds from it. Report the distribution, sample count and proposed margin. Write an environment-bound fixture calibration only when decode succeeds and interval checks pass; fail on impossible future content. This measures the fixture path, not arbitrary game/compositor timing.
  - `m0.clock.server-mono`: the calibration uncertainty distribution, with an `xdotool` click whose server time, mapped through calibration, matches the fixture's recv `mono_ns` within uncertainty plus delivery.
- **Artifacts**: sample frames converted to PNG, `lag.csv`, `calibration.json`.
- **Out of scope / escalate**: video and multi-monitor scale (only recorded in `env.json`). A missing calibration or lag beyond the calibrated bound blocks dispatch; report and rerun calibration explicitly. [P0.6](P0.6.md) waits for the settle boundary plus the bound before capturing, so freshness does not fail predictably on every second action. Live environments need their own measured profile.
