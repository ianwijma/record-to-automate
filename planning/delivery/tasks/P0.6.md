# P0.6 First runnable CLI: fixed replay with ordinary diagnostics

[Delivery index](../../DELIVERY-PLAN.md) · [Milestone M0](../milestones/M0.md) · [Implementation plan](../../IMPLEMENTATION-PLAN.md) · [Requirement and W-package mapping](../coverage.md)

Read [execution rules](../execution.md) and [safety invariants](../safety.md) before executing. Consult [experimental defaults](../defaults.md) for implementation constants and [validation contract](../validation.md) when implementing or running acceptance cases. Follow linked dependencies for their contracts; execute only this packet.

- **Outcome**: `bun packages/engine/src/cli.ts run <workflow.json> --target-class r2a-x11-target` replays fixed clicks safely.
- **Depends on**: [P0.4](P0.4.md), [P0.5](P0.5.md).
- **Files**: `packages/engine/{package.json,src/cli.ts,src/run.ts,src/dispatch.ts,src/trace.ts,src/locators/fixed.ts,src/stop.ts,src/window.ts,test/*.test.ts}`, `fixtures/workflows/m0-fixed.json`, `validation/cases/m0/engine.ts`, `validation/milestones.ts`.
- **Steps**:
  1. Use workflow format `r2a.workflow/0`: `{schema, target:{wmClass}, actions:[{id, kind:"click", locator:{kind:"fixed", point:{x,y}}, button}]}`. Points are relative to the window.
  2. Find the window by `WM_CLASS`, walking `_NET_CLIENT_LIST` or root children. If there is no match or more than one, stop with `TargetWindowNotFound` or `TargetWindowAmbiguous`.
  3. Start the capture worker and guard, open a run generation, `ARM`, and start the heartbeat. Heartbeats do not authorize input; every request is independently checked.
  4. For each action:
     1. Wait until the preceding known settle boundary plus measured capture-lag bound, then capture a new frame.
     2. Assert `obs.content.earliest > settleBoundary` when a previous action exists; the first action has no prior effect fence.
     3. Reject nonfinite/out-of-window points, compute root coordinates from `rootRect` and the validated point, and set `deadline = obs.content.earliest + permitValidityMs`.
     4. Record `{runId, actionId, generation, seq, obs, frameHash, deadline}` in a bounded in-memory trace and append ordinary diagnostics to `journal.jsonl`. Do not fsync or wait for production asset publication before input. A known write failure stops; a crash can lose diagnostics. This is explicitly non-durable preview evidence.
     5. `SUBMIT`.
     6. Await the ACK or an error within `ackTimeoutMs`. A timeout becomes `OutcomeUnknown`.
     7. Set `settleBoundary = ack.t_end + settleMs`; observe a post-action frame after that boundary before the next action. A failed/unknown settle stops with `OutcomeUnknown`.
  5. Any `ERR` becomes a typed stop with explanation `{step, expected, observed, reason, dispatched:boolean}`. There is no retry.
  6. Record capture, locate, diagnostic enqueue, submit, check and dispatch timestamps; durability stages are `not implemented`, not zero-cost measurements. Register M0 as `current` and run the fixture loop from the default validator.
- **Contracts/errors**: stop reasons `TargetWindowNotFound`, `TargetWindowAmbiguous`, `CaptureFailed`, `Rejected(<E_*>)`, `OutcomeUnknown`, `Aborted(<route>)`, `EvidenceWriteFailed`. Restart never resumes/retries a run; a new explicit run starts from a fresh observation. Journal records are `intent`, `result`, `stop`. Exit codes: 0 completed, 3 stopped, 4 aborted.
- **Acceptance**: `bun run validate` executes the M0 runnable loop and implemented safety cases; `--case m0.engine.*` isolates failures. Explicit `--suite m0` still reports outstanding fault/attendance evidence (§5).
- **Artifacts**: `journal.jsonl`, `gl-latency.csv`, and the guard and fixture ledgers.
- **Out of scope / escalate**: image locators ([P1.3](P1.3.md)), UI and branches.

**M0 guard, engine and abort cases.** All use real Xvfb; check guard dispatch and fixture receipts separately. Rejected requests yield zero new receipts; abort may emit cleanup releases, which are counted separately from new actions. Compare server-processed receipt sequence/barriers rather than assuming application receive time equals dispatch time.

| Case | Setup → expected |
| --- | --- |
| `m0.guard.not-armed` | Request before ARM → `E_NOT_ARMED`, no injection |
| `m0.engine.fixed-replay` | Three clicks on `grid` → exactly matching points/buttons/order |
| `m0.engine.fresh-frame` | Each action uses a distinct observation after the prior settle fence; stale observation → `E_STALE_OBSERVATION` |
| `m0.guard.stale-deadline` | Expired request → `E_EXPIRED`, no injection |
| `m0.guard.reuse` | Same generation/sequence twice → `E_EFFECT_SEQ` on reuse |
| `m0.guard.effect-seq` | Out-of-order sequence → `E_EFFECT_SEQ` |
| `m0.guard.recipient-cover` | Cover point before dispatch check → `E_RECIPIENT`, no injection into either window |
| `m0.guard.geometry-moved` | Move target after observation → `E_GEOMETRY` |
| `m0.guard.busy` | Hold dispatch at test barrier, submit another request → `E_BUSY` |
| `m0.engine.unknown-no-retry` | Drop ACK → `OutcomeUnknown`, no resubmission or next action |
| `m0.abort.pipe-pending` | One request pending at barrier; direct pipe abort → revoked, no new action |
