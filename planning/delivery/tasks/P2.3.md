# P2.3 Recorder: ring frames, filtered events, extraction and target drafts

[Delivery index](../../DELIVERY-PLAN.md) · [Milestone M2](../milestones/M2.md) · [Implementation plan](../../IMPLEMENTATION-PLAN.md) · [Requirement and W-package mapping](../coverage.md)

Read [execution rules](../execution.md) and [safety invariants](../safety.md) before executing. Consult [experimental defaults](../defaults.md) for implementation constants and [validation contract](../validation.md) when implementing or running acceptance cases. Follow linked dependencies for their contracts; execute only this packet.

- **Outcome**: a recording on the fixture produces source files that subsequent edits leave untouched and a draft workflow of clicks and physical keys, each click with a pre-frame and an image-target draft.
- **Depends on**: [P0.7](P0.7.md), [P2.1](P2.1.md), [P2.2](P2.2.md); [P1.3](P1.3.md) for image-draft integration. Fixed-only recording can proceed if matcher evidence remains incomplete, with image cases missing. D-EMERGENCY-TAKE only for saving an emergency-interrupted take.
- **Files**: `native/x11/capture/capture.c` (add the `RING_START fps frames` and `RETAIN around_ns before after dir` verbs), `packages/recording/{package.json,src/session.ts,src/extract.ts,src/take.ts,test/extract.test.ts}`, `validation/cases/m2/record.ts`.
- **Steps**:
  1. A record lease starts the capture ring at `recordFps` with `ringFrames` frames and starts the observer for the target.
  2. For each target press, request the frames before and after it. The pre-frame is the latest frame with `content.latest < mapped_event_time.earliest`. If there is none, flag `no-pre-frame`.
  3. Extraction:
     - A press and release of the same button within 4 px is a `click`.
     - Anything else is an `unsupported:drag` step, which is non-runnable until [P4.1](P4.1.md).
     - A supported single key down/up pair is a `key` step holding physical code namespace, keycode, keysym, modifiers and the captured XKB keymap/layout fingerprint. It is never text. Chords/repeats/unknown edges are blocked drafts until [P4.1](P4.1.md)/[P4.2](P4.2.md); do not replay unsupported combinations.
  4. Generate an image-target draft for each click ([P1.2](P1.2.md)), awaiting explicit review in the preview UI; propose `image` when the self-test is `ok`, otherwise leave it a flagged image draft with Run blocked. The user may explicitly select Fixed; recording failure never silently changes the locator method.
  5. Pause discards events and does not buffer them. A GAP stops recording with an explicit gap (no extraction across it), and the take is labelled `incomplete`. Emergency stop marks the in-memory take incomplete and blocks saving it until D-EMERGENCY-TAKE is resolved; no draft retention choice is labelled approved.
  6. Finalize the source take as `take.json` plus the target-only `events.jsonl` and frame assets. Use the PNG encoder already selected for [P1.1](P1.1.md), pinning its actual dependency; never invent an unlisted native prerequisite.
- **Contracts/errors**: `E_RECORD_GAP`, `E_TARGET_LOST`, `E_LEASE_BUSY`. Takes never contain non-target events.
- **Acceptance**: `bun run validate --case m2.record.*` on Xvfb with a synthetic driver.
  - `m2.record.clicks-keys`: the extracted steps match the driver script.
  - `m2.record.preframe-conservative`: each pre-frame's interval precedes the event.
  - `m2.record.nontarget-sentinel`.
  - `m2.record.pause-discards`.
  - `m2.record.overflow-gap`.
- **Artifacts**: take directory and extraction diff.
- **Out of scope / escalate**: drag, scroll, double-click and holds ([P4.1](P4.1.md)), and reference video ([P4.8](P4.8.md)).
